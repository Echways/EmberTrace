# Бинарный формат сессии (`.ember`)

`EmberTrace.Format` сохраняет остановленную сессию в компактный бинарный файл и читает его обратно в полноценный
`TraceSession`, пригодный для анализа.

```bash
dotnet add package EmberTrace.Format
```

## Сохранение и загрузка

```csharp
var session = Tracer.Stop();

TraceFormat.Write(session, "out/session.ember");

var reloaded = TraceFormat.Read("out/session.ember");
Console.WriteLine(TraceText.Write(reloaded.Process(), reloaded.Metadata));
```

Для обоих направлений есть перегрузки со `Stream`:

```csharp
using var fs = File.Create("out/session.ember");
TraceFormat.Write(session, fs);
```

## Потоковое чтение и сжатие

`TraceFormat.OpenRead` возвращает `TraceStream`: заголовок, имена потоков, метаданные и окружение доступны сразу, а
`Events` лениво декодирует файл в порядке файла (он уже отсортирован по времени), не строя `TraceSession`.
Используйте его для трасс, которые неудобно держать в памяти целиком.

```csharp
using var trace = TraceFormat.OpenRead("out/session.ember.gz");
var scopes = new ScopeReader(trace.Events, trace.EndTimestamp);
```

`Events` можно перечислить один раз. Путь, оканчивающийся на `.ember.gz`, записывается со сжатием gzip
(`CompressionLevel.Fastest`); `Read` и `OpenRead` определяют gzip по сигнатуре, как бы ни назывался файл. Обрезанный
или повреждённый gzip приводит к `InvalidDataException`. `OpenRead` требует, чтобы имена потоков и метаданные шли
до событий, как их пишет писатель; для `Read` такого требования нет.

## Почему не Chrome Trace JSON

Chrome Trace JSON — формат отображения: он лишён части данных, многословен и медленно парсится. `.ember` хранит все
поля каждого события, занимает в несколько раз меньше места и загружается в тот же конвейер анализа, что работает
в процессе.

## Что сохраняется

- Заголовок: версия формата, частота таймера, границы сессии, момент начала сессии в UTC, число событий и счётчики
  потерь/сэмплирования.
- Имена потоков.
- Метаданные (имя и категория) для каждого id, который реально встречается в трассе.
- Окружение (версия формата 2): настройки машины и рантайма на старте и на остановке (ОС, рантайм, GC, тиринговая
  компиляция, переменные `DOTNET_*`, governor и turbo процессора в Linux, affinity, лимиты cgroup) и метки
  `SessionOptions.Tags` с префиксом `tag.`. `EnvironmentCompatibility.Compare` показывает, какие различия между двумя
  записями делают сравнение времён ненадёжным.
- Все события в глобально отсортированном порядке.

## Что не сохраняется

- `SessionOptions`. Он хранит делегаты и влияет только на запись; загруженная сессия получает опции по умолчанию.
- Исходная раскладка по чанкам. События восстанавливаются как отсортированная последовательность, поэтому для сравнения
  используйте `EnumerateEventsSorted()`, а не `EnumerateEvents()`.

## Таймстемпы между машинами

`Stopwatch.Frequency` машины, на которой велась запись, хранится в заголовке и путешествует вместе с файлом, поэтому
длительности считаются верно, даже если трасса снята на одной машине, а анализируется на другой.

## Совместимость

Заголовок содержит версию формата. Читатель отказывается открывать файл, записанный более новой версией, бросая
понятный `InvalidDataException`, вместо того чтобы истолковать его неверно. Повреждённые и обрезанные файлы приводят
к `InvalidDataException` или `EndOfStreamException`.

Заголовок хранит собственный размер. Читатель пропускает незнакомые ему байты заголовка, поэтому файлы, записанные
более новой сборкой той же версии формата, остаются читаемыми; файл, записанный до появления UTC-метки начала,
загружается с `StartedAtUtc == null`.

Версия формата 2 добавляет секцию окружения. Читатель принимает версии 1 и 2; файл версии 1 загружается с
`Environment == null`, а сравнение его с другой записью даёт предупреждение, а не ошибку. Писатель всегда пишет
версию 2, поэтому более старые сборки такой файл не откроют. Неизвестный id секции в любой версии приводит к
`InvalidDataException`.
