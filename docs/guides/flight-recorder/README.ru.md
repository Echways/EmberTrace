# Flight recorder

Flight recorder держит в памяти ограниченное окно недавнего прошлого и позволяет выгрузить его
*не останавливая сессию*. Это превращает EmberTrace из инструмента для бенчмарков в то, что
можно оставить работать в сервисе: поймали таймаут, вылез 99‑й перцентиль, прилетело
исключение — дампим последние секунды трейса и продолжаем писать.

## Включение

```csharp
Tracer.Start(new SessionOptions
{
    OverflowPolicy = OverflowPolicy.DropOldest,
    MaxRetentionWindow = TimeSpan.FromSeconds(10),
    MaxTotalChunks = 256
});
```

- `OverflowPolicy.DropOldest` обязателен. С любой другой политикой `MaxRetentionWindow`
  бросает `ArgumentException`: отбрасывать *новые* события — прямая противоположность
  flight recorder.
- `MaxRetentionWindow` ограничивает буфер по времени, `MaxTotalChunks` — по памяти.
  Задавайте оба: окно — то, что нужно по смыслу, лимит чанков — страховка процесса при
  всплеске нагрузки.
- Окно применяется при ротации чанка писателем и ещё раз при снятии снапшота. Чанк, которым
  всё ещё владеет простаивающий поток, не обрезается — такой поток сохраняет свой последний
  неполный чанк.

## Снятие снапшота

```csharp
var snapshot = Tracer.Snapshot();
var recent = Tracer.Snapshot(TimeSpan.FromSeconds(5));
```

`Snapshot()` копирует всё, что сейчас в буфере. `Snapshot(window)` — только события с
меткой `>= now - window`; это то, что нужно, когда буфер держит 60 секунд, а инцидент занимает
5.

Результат — обычный `TraceSession`. С ним работает всё, что работает с остановленной сессией:
`Process()`, `TraceText.Write(...)`, `TraceExport.*`, `TraceFormat.Write(...)`:

```csharp
try
{
    await HandleRequestAsync(request, timeout);
}
catch (TimeoutException)
{
    TraceFormat.Write(Tracer.Snapshot(TimeSpan.FromSeconds(10)), $"/var/log/trace-{DateTime.UtcNow:O}.ember");
}
```

## Что снапшот гарантирует

- **Сессия продолжает работать.** `Tracer.IsRunning` остаётся `true`, писатели не
  останавливаются, ни одно событие не теряется из‑за снятия снапшота.
- **Буфер не опустошается.** Два снапшота подряд пересекаются. Буфер чистят только окно
  хранения и политика переполнения.
- **События не рвутся.** Снапшот копирует консистентный срез каждого чанка. Чанки, которые
  были бы переиспользованы во время копирования, откладываются и освобождаются после.
- **`EndTimestamp` — это точка среза.** Для каждого события снапшота выполняется
  `Timestamp <= EndTimestamp`.
- **`IsSnapshot` равен `true`** и переживает round‑trip через `TraceFormat`.

## Чего снапшот не гарантирует

- **Это не глобальный мгновенный срез.** Потоки копируются последовательно, барьера между
  ними нет. Для трейса это верный размен: важна корректность каждого события, а не
  одновременность всех.
- **Скоупы, открытые на момент среза, выглядят незакрытыми.** `ScopeReader` синтезирует им
  закрытие в `EndTimestamp` — ровно как для сессии, остановленной внутри скоупа, — и помечает
  шаг как `IsSynthetic`. Потребители, пропускающие синтетические шаги, пропустят и эти:
  Chrome Trace экспортёр не выдаст complete-спан для скоупа, открытого на момент среза. Это
  то же поведение, что и у сессии, остановленной внутри скоупа.
- **Окно может отрезать `Begin` скоупа.** Осиротевший `End` учитывается в
  `ScopeReader.UnmatchedEndCount` и отбрасывается. Если это важно — расширьте окно.

## Цена

Горячий путь записи не изменился: в запись события не добавлено ни одной инструкции. Снапшот
стоит одного `Array.Copy` на чанк плюс короткого захвата лока для снятия списка чанков. Пока
снапшот в полёте, буфер может держать до двух своих обычных размеров — переиспользование
чанков откладывается до конца копирования, излишек возвращается в пул сразу после.

`TraceSession.DroppedEvents` и `DroppedChunks` включают события, вытесненные окном хранения.
Устаревание — не переполнение: само по себе оно не выставляет `WasOverflow` и не вызывает
`OnOverflow`.
