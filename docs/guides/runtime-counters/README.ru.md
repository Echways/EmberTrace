# Runtime-счётчики

EmberTrace умеет снимать метрики здоровья .NET-рантайма на ту же временную шкалу, что и ваши scope'ы: медленный
scope и вызвавшая его сборка Gen2 совпадают визуально.

## Включение

```csharp
Tracer.Start(new SessionOptions
{
    RuntimeCounters = RuntimeCounters.All,
    RuntimeCounterInterval = TimeSpan.FromMilliseconds(50)
});
```

По умолчанию счётчики выключены. Группы комбинируются как флаги:

| Флаг | Что пишет |
|------|-----------|
| `Gc` | Счётчики сборок Gen0 / Gen1 / Gen2 как дельты за интервал |
| `Memory` | Размер кучи (абсолютное) и аллоцированные байты (дельта за интервал) |
| `ThreadPool` | Число потоков и длина очереди (абсолютные), завершённые задачи (дельта) |
| `Exceptions` | Число first-chance исключений как дельта за интервал |
| `GcPauses` | Приблизительные интервалы GC-пауз |
| `All` | Всё перечисленное |

## Дельты и датчики

Накопительные счётчики рантайма пишутся как дельты с прошлого сэмпла. Монотонно растущая линия на counter-дорожке
прячет ровно те всплески, которые вы ищете; дельта их показывает. Датчики — размер кучи, число потоков, длина
очереди — пишутся абсолютными значениями. Первый сэмпл выдаёт ноль для каждой дельты, потому что он задаёт базу.
Счётчик, поехавший назад, зажимается в ноль, а не даёт отрицательную скорость.

## Где появляются счётчики

Сэмплер работает на отдельном фоновом потоке с именем `EmberTrace.Runtime`, поэтому его события попадают на
собственную дорожку и рисуются отдельной строкой в Perfetto, под дорожками ваших scope'ов.

## Зарезервированные id

Runtime-счётчики используют отрицательные trace-id, перечисленные в `RuntimeCounterIds`. `Tracer.Id` маскирует
хеш через `0x7fffffff` и никогда не возвращает 0, поэтому пользовательский id всегда положителен и не может
пересечься с этим диапазоном. Используйте `RuntimeCounterIds.IsReserved(id)`, чтобы отфильтровать собственные
события EmberTrace из отчёта.

```csharp
var session = Tracer.Stop();

foreach (var e in session.EnumerateEventsSorted())
    if (!RuntimeCounterIds.IsReserved(e.Id))
        Handle(e);
```

## Фильтры категорий не применяются

Runtime-счётчики обходят `EnabledCategoryIds` / `DisabledCategoryIds`. Ими управляет только `RuntimeCounters`,
поэтому allowlist категорий не может молча выбросить счётчики, которые вы явно запросили.

## Точность GC-пауз

`GCMemoryInfo` сообщает длительность паузы, но не её абсолютное начало, поэтому интервал паузы рисуется
заканчивающимся на том сэмпле, который его увидел. Позиция точна лишь до интервала сэмплирования; длительность
при этом точная. Уменьшайте `RuntimeCounterInterval` ради лучшей позиции — ценой большего числа сэмплов.

## Стоимость

Сэмплер — это один фоновый поток с приоритетом `BelowNormal`, делающий несколько чтений свойств за интервал.
Он пишет через тот же lock-free путь, что и любое другое событие, и ничего не добавляет к горячему пути вашего
приложения. При интервале по умолчанию в 50 мс он даёт примерно 200 событий в секунду.
